# OnePage Resume Builder

A **free** one-page resume builder for everyone — school students, college students, freshers, experienced professionals, managers, freelancers and career changers, technical or not. Fill in only the sections that apply to you, watch a live A4 preview, and download a real, ATS-friendly, text-based PDF that is guaranteed to be exactly one page.

No paid plans, credits, watermarks or premium templates. You never need an account to build or download a resume; an account only adds saving.

## Main features

- **Guided flow:** Profile → Details → Sections → Template → Download.
- **Dynamic sections:** choose a career stage *and* a professional field; you start with the relevant sections, can add/remove/rename/hide/reorder sections and entries, and add custom sections.
- **One page, always:** live A4 preview, a page-fit meter ("14 lines to spare"), automatic spacing compaction (never below 9pt text), and a clear warning plus one-click suggestions (hide / shorten) when content overflows. Nothing is ever silently dropped — hiding a section keeps its data.
- **Real PDF export:** generated by headless Chrome from the *same* components and CSS as the preview; selectable text, clickable links, Unicode (Latin scripts), exactly one A4 page.
- **Six templates:** Modern Professional, Minimal/Clean, Student/Academic, Technical/Developer, Corporate/Traditional, Creative/Modern. All single-column, no tables or images. Switching never changes content.
- **Demo mode (no login):** five fictional sample profiles clearly marked **DEMO**, stored only in the browser tab, never mixed with real data.
- **Accounts (optional):** register/login, dashboard, save/edit/delete resumes, download saved resumes, account settings (name, password, delete account).
- **Responsive & accessible:** split screen on desktop, step form + Edit/Preview toggle on mobile, dark mode, keyboard navigation, skip link, ARIA labels, reduced-motion support.

### Supported profiles

Career stage: School Student · College Student · Recent Graduate · Fresher / Entry-Level · Experienced Professional · Manager / Team Lead · Freelancer / Consultant · Other / Career Changer.
Field: Technical / Software · Sales & Marketing · Finance & Accounting · Human Resources · Operations/Admin/Project Coordination · Customer Support · General.

The stage selects the starting sections (e.g. school students get *School, Academic Achievements, Extracurriculars, Sports, Volunteer, Skills, Languages, Interests* — no work experience forced on them). The field tunes the skill groups (e.g. technical → *Languages, Frameworks, Databases, Cloud & DevOps, Tools*). Changing profile later only **adds** sections; it never removes your content.

## Architecture & folder structure

```
shared/            Pure JS used by BOTH browser and server (single source of truth)
  sections.js        section-type registry: labels, limits, layout
  profiles.js        stages x categories -> starting resume
  schema.js          zod schema + export checks
  resumeOps.js       immutable edit operations (add/move/remove/switch profile)
  fit.js             density levels, fit status, overflow suggestions
  templates.js       template registry
  demoData.js        fictional DEMO profiles
src/               React app
  resume/            ResumeDocument.jsx + resume.css (the A4 resume), fitDom.js (measurement)
  components/builder/  step forms, preview, fit meter
  pages/             Landing, DemoPicker, Builder, Dashboard, Settings, Auth, static pages
  context/ hooks/ api/ lib/
server/            Express API
  app.js config.js db.js (migrations) auth.js http.js
  routes/            auth.js resumes.js pdf.js
  pdf/               html.jsx (builds printable HTML), service.js (Chrome pool)
tests/             unit/  api/  e2e/
```

Data model (stored as JSON in `resumes.data`, validated on every write):

```
{ version, templateId, profile:{stage,category}, basics:{name,title,email,phone,location,linkedin,github,website,summary},
  sections:[{ id, type, title, visible, items:[{ id, heading, subheading, date, meta, text }] }] }
```

Section *types* (`school, education, experience, projects, skills, achievements, certifications, activities, volunteer, coursework, languages, interests, custom`) define which item fields exist, their labels and character limits (`shared/sections.js`). Users can create any number of titled sections from these types, which is how custom and profile-specific sections work without a complex schema.

### How one-page fit works

1. A hidden probe renders the resume at fixed A4 size. `measureFit()` (`src/resume/fitDom.js`) tries density 0→3 (spacing tightens first; font steps 10 → 9.5 → 9pt, **never lower**) and measures real rendered height.
2. The first density that fits is used. If even the tightest overflows, the UI shows the overflow, disables download, and suggests hiding the lowest-priority sections or shortening the longest one.
3. Character limits (from the brief) are enforced as input limits, but **real rendered height** is what decides fit.
4. The server runs the *same* `measureFit` function inside headless Chrome before printing, refuses with `422 OVERFLOW` if it does not fit, and verifies the PDF has exactly one page. Preview and PDF therefore agree on density (asserted by the E2E tests).

## Local setup

Requirements: Node.js ≥ 20, npm, and Google Chrome or Chromium (for PDF export).

```bash
npm install
cp .env.example .env        # optional; defaults work for local development
npm run dev                 # API on :3001 + Vite on :5173 (proxied)
```

Open http://localhost:5173.

Production-style run:

```bash
npm run build
NODE_ENV=production npm start   # serves API + built app on http://localhost:3001
```

### Environment variables (`.env.example`)

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3001` | API port |
| `NODE_ENV` | `development` | `production` enables secure cookies and static serving of `dist/` |
| `CLIENT_ORIGIN` | `http://localhost:5173` | Allowed browser origin (CSRF check) |
| `DATABASE_PATH` | `./data/app.db` | SQLite file (created automatically) |
| `SESSION_TTL_DAYS` | `14` | Session lifetime |
| `BCRYPT_ROUNDS` | `12` | Password hashing cost |
| `TRUST_PROXY` | `0` | Set `1` behind a reverse proxy |
| `MAX_RESUMES_PER_USER` | `25` | Saved resume cap |
| `CHROME_PATH` | auto-detect | Chrome/Chromium executable |
| `PDF_NO_SANDBOX` | `0` | Set `1` only in containers that can't sandbox Chrome |
| `RATE_LIMIT_AUTH_MAX` / `_PDF_MAX` / `_API_MAX` | `10` / `20` / `300` | Rate limits |

No secrets are required; sessions are random opaque tokens stored (hashed) in SQLite. `.env`, `data/` and `*.db` are git-ignored.

### Database & migrations

SQLite tables: `users`, `sessions`, `resumes` (+ `schema_migrations`). Migrations live in `server/db.js` (`MIGRATIONS`), are applied automatically at startup inside a transaction, and are append-only. Foreign keys cascade, so deleting an account removes its sessions and resumes.

## Authentication flow

- `POST /api/auth/register|login` set an **HttpOnly, SameSite=Lax** cookie (`Secure` in production). Only a SHA-256 hash of the session token is stored.
- Passwords: 10–72 chars with a letter and a number; bcrypt-hashed. Login failures return one generic message and cost the same for unknown emails.
- Changing the password signs out all other sessions. Account deletion requires the password.
- Password reset by email is **not** implemented (no mail infrastructure) — see limitations.

## Demo mode

`/demo` → pick a fictional profile → `/demo/:id`. Edits live in `sessionStorage` only, a permanent **DEMO** banner is shown, no account calls are made, and "Start my own resume" opens a fresh, separate draft. PDF download works without login (the public `/api/pdf` endpoint is rate-limited and strictly validated).

A guest's own draft (`/builder/new`) is kept in `localStorage`; logging in lets them save it to the account. Demo, guest draft and account data are never mixed or silently switched.

## PDF export

`POST /api/pdf` validates the resume (same schema), renders `ResumeDocument` to static HTML with inlined fonts and CSS (`server/pdf/html.jsx`), loads it in headless Chrome with **all network requests blocked** and a strict CSP, measures fit, prints with `@page { size: A4; margin: 0 }`, then checks for exactly one page. If Chrome is unavailable the API returns `503 PDF_UNAVAILABLE` and the UI offers a browser *Print → Save as PDF* fallback using the same A4 markup.

## API

All endpoints are under `/api`, JSON in/out, errors as `{ "error": { "code", "message", "details?" } }`.

| Method & path | Auth | Description |
|---|---|---|
| `GET /health` | – | Liveness |
| `POST /auth/register` | – | `{email,name,password}` → 201 + cookie |
| `POST /auth/login` | – | `{email,password}` |
| `POST /auth/logout` | – | Ends session |
| `GET /auth/me` | – | `{user}` or `{user:null}` |
| `PATCH /auth/me` | ✔ | `{name}` |
| `POST /auth/password` | ✔ | `{currentPassword,newPassword}` |
| `DELETE /auth/me` | ✔ | `{password}`; deletes account + data |
| `GET /resumes` | ✔ | List own resumes (summary) |
| `POST /resumes` | ✔ | `{title,data}` → 201 |
| `GET /resumes/:id` | ✔ | Own resume (404 for anyone else's) |
| `PUT /resumes/:id` | ✔ | `{title?,data?}` |
| `DELETE /resumes/:id` | ✔ | Delete |
| `POST /pdf` | – | `{resume}` → `application/pdf` (422 `OVERFLOW`/`INCOMPLETE`, 503 `PDF_UNAVAILABLE`) |
| `GET /pdf/status` | – | `{available}` |

## Security notes

- Strict server-side validation (zod) on every write; per-field limits, item/section caps, http(s)-only links, control characters stripped. React escapes all text; the PDF HTML is generated through React too.
- Every resume query is scoped by `user_id` (unknown and foreign IDs both 404, so IDs can't be probed). Prepared statements only.
- CSRF: SameSite=Lax cookie + JSON-only bodies + `Origin` check on state-changing requests.
- Helmet headers incl. CSP; `x-powered-by` removed; 200 KB body limit; rate limits on auth, PDF and the whole API; error logs never include bodies or passwords.
- PDF renderer: no network, CSP `default-src 'none'`, concurrency cap, per-render timeout.
- The original project had no backend, secrets or `.env`. A scan of the working tree and full git history found **no committed credentials**, so nothing needs rotating. (History was not rewritten.)

npm run test:e2e  # builds the app and drives headless Chrome through the real UI
npm run test:all  # everything

Coverage includes: every profile × field, demo data, schema limits and rejection of bad input, section/item reorder and template switching preserving content, no gaps for empty sections, HTML/URL injection, register/login/logout/rate limiting, saving and retrieving resumes, cross-user isolation, CSRF/media-type guards, PDF page count (every demo × template, short and limit-length content, overflow refusal), and browser flows at mobile/tablet/desktop widths.

## Limitations

- No password-reset-by-email or email verification (needs an email provider).
- PDF export needs Chrome/Chromium on the server; otherwise the print fallback is used.
- Fonts bundled cover Latin/Latin-Extended scripts; other scripts (e.g. CJK, Devanagari) fall back to system fonts and may differ between preview and server PDF.
- No drag-and-drop reordering (accessible up/down buttons instead); no DOCX export.
- Saved-resume edits are last-write-wins (no multi-device conflict handling).
